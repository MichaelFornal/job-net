Outcome is a separate axis from the mark. The lowercase keys record what you did; shift records what they did, and a rejected application is still an application that was sent. Keeping them apart is the whole point: 188 applications went out across ten days with 73% into one lane and no way to tell whether that lane converted at 5% or 0%. Run apply/inbox_read.py --write to backfill these from Gmail rather than typing them in.

Each filter key cycles its own chips; the three stack, and the number on a chip is what you get by clicking it — the current filter with that one row lifted. The tab badges count the filtered set too, so to go means to go here, not in the whole queue. Filters stick across tab switches and reloads; Esc clears the lot.

Sort is not a filter — it reorders the queue without changing what is in it, so it carries no count, Esc leaves it alone, and every tab badge reads the same under all three. Fit is the ranking this page has always used: employer boards before aggregators, strongest AI band first. Newest and Oldest put the posting date in front of that instead. Anything in flight stays pinned to the top either way, and postings whose source never published a date sort last, not first — blank means unknown, not old.

Applying is for a form you opened and did not finish — a long application, one waiting on a referral, one you saved a draft of. It stamps no date and does not fill the progress bar; only a does. Marking it applied later stamps that day, not the day you started.

Shift-click a mark box to set every row between the last one you marked and that one — the fast way to log a run you already applied to.

Marks save as you go and survive every rebuild. Run python3 triage_export.py any time for the workbook.
